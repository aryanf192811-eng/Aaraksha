Methodology

No single numeric SIH rubric with published weightages is public. Three independent sources converge on the same shape, so that's what this is scored against: the idea-portal's five-category framework — Innovation, Invention, Technical Feasibility, Impact and Benefits, Architecture — which is the actual field labels used for both problem-statement shortlisting and internal-hackathon evaluation; and the grand-finale live-judging model, where panels score 1–20 per factor across three rounds, combined into a total out of 100. A prior gap-analysis pass (the research PDF this project's earlier work was based on) independently converged on the same five-way split. Each category below is scored out of 20 on that confirmed scale, summed to the headline number — the same arithmetic the finale itself uses.

  • sih.gov.in — official portal; problem-statement idea-submission fields (Innovation / Invention / Technical Feasibility / Impact & Benefits / Architecture Diagram)
  • Cross-referenced evaluation summaries describing a 1–20-per-factor, three-round, /100 grand-finale scoring model across solution appearance, impact, technology, execution, and UX
  • The team's own prior gap-analysis research (SIH Tourism Project Gap Analysis) — independently arrived at the same five-category shape

Criterion by criterion

01

Innovation

18/20
Earns it

A tamper-evident Journey Integrity Hash — a real SHA-256 chain over itinerary, check-ins, SOS events, and government checkpoint scans, independently recomputable live via one API call — answers the "blockchain-based Digital ID" requirement most teams meet with a static ID card image. Offline SOS over raw structured SMS, a rule-based anomaly detector that flags a gone-quiet or off-route tourist before anyone presses a button, and a unified Rapido-style rescuer network merging official teams and citizen volunteers into one live-tracked, weighted-dispatch pool are each genuinely uncommon in this problem space.

Gap

No single feature is a from-scratch invention — the strength is in assembling several honestly-built real techniques (hash chains, gradient descent, on-device CV, real road routing) rather than one unprecedented idea. A judge looking for "the one thing nobody else thought of" will find a system, not a single hook.

02

Invention

16/20
Earns it

The clearest invention is a stance, not a component: a genuinely trained logistic-regression Predictive Risk Model runs alongside — never instead of — an honestly rule-based Travel Safety Index, both explicitly labeled for what they are. Most competing "AI" claims are an LLM call with a prompt attached; this is real gradient descent with a printed loss curve and held-out test accuracy the team is willing to show, including its weaknesses.

Gap

Individually, SOS buttons, Dead Man's Switches, and TSI-style scores already exist in prior SIH Travel & Tourism winners (per the team's own gap-analysis research). The novelty is in the combination and the honesty, not in any one primitive being unseen before.

03

Technical Feasibility

19/20
Earns it

Not a mockup: 101 real endpoints across a 23-table Postgres schema, four working portals, and a backend that survived a deliberate adversarial pass — rate-limit bypass attempts, SQLi payloads, forced transaction rollbacks, a concurrent double-resolve race — with eight real defects found and fixed, including a live unauthenticated path to govt SUPER_ADMIN. Every external integration (Twilio, Gemini, OpenWeatherMap) degrades gracefully when unconfigured rather than failing the request. Every feature this session was verified live against a running server and database, not asserted.

Gap

Single Postgres instance with no documented horizontal-scaling story, and live road routing depends on the public OSRM demo server — free and unowned infrastructure, not something a state government could depend on at scale without standing up its own instance. A judge probing "what happens at 10,000 concurrent tourists" will find an honest gap here, not a bad answer, but a gap.

04

Impact and Benefits

17/20
Earns it

Targets the named problem directly — Northeast Indian terrain where signal genuinely disappears — with a mechanism built for exactly that (offline SOS over SMS, not a feature that quietly assumes connectivity). DPDP Act 2023 data rights and a GIGW 3.0 / WCAG 2.1 AA accessibility pass on the government-facing portal are real legal- and inclusion-impact stories a judging panel can be shown, not just claimed. Four cooperating portals reflect the real stakeholder ecosystem — tourist, family, government, rescuer — rather than optimizing for one audience.

Gap

Every account and scenario is a seeded demo. There is no field data — no real tourist, district officer, or volunteer has used this outside the team. Impact is architecturally credible, not empirically validated, and a panel that asks "who has actually used this" has a true but unsatisfying answer.

05

Architecture

17/20
Earns it

A consistently layered backend (Route → Middleware → Controller → Service → Repository) across all 15 route groups, 15 schema migrations applied as reviewable named diffs rather than hand-edited tables, and a production-readiness report with hand-drawn diagrams tracing the real request pipeline, transaction boundaries, and SOS/DMS/TSI lifecycles from actual source code — not a stock architecture slide.

Gap

No documented business or deployment model — funding path, state-government procurement route, or rough cost-per-tourist economics. The system architecture is thoroughly documented; the business architecture around it is not, and SIH panels routinely ask for both.

What would actually move the number

  • 1

    A one-slide business/deployment model. State-government procurement pathway, rough cost-per-tourist, who operates the Govt Command Center in production. This is the single largest gap and the only one that isn't a code problem.

  • 2

    Any real field signal. Even five to ten informal testers walking the offline-SOS flow with airplane mode on beats another polished feature — panels notice the difference between "built for" and "used by."

  • 3

    Rehearse the accessibility answer. The GIGW 3.0 / WCAG 2.1 AA pass on the Govt Command Center has now shipped — contrast tokens, keyboard-accessible modals, labeled form fields. The remaining work is being ready to demonstrate it live if a judge asks, not building more of it.

  • 4

    A rehearsed 90-second opening. Lead the demo with the hash-chain reveal, the offline-SMS SOS, and the honest rule-based-vs-trained-model distinction — the most differentiated material shouldn't surface on question five.

Corrections to a second-opinion critique

A separate external review raised two "remaining gaps" worth checking against the actual repository before repeating them to a judge — both turn out to already be closed, and presenting them as open would cost points rather than win them.

Claimed

"Command center relies on flat 2D Leaflet mapping" — no 3D or spatial computing.

Actual

The Govt Command Center has a one-tap 2D/3D toggle rendering real elevation relief — TerrainMap.tsx (MapLibre GL JS + free AWS-hosted Terrarium elevation tiles, no paid API key), wired into LiveMapPage.tsx's viewMode state. A rescuer's live GPS marker already moves across genuine mountain-ridge topology, not a flat plane.

Claimed

Gemini is used "strictly to explain pre-computed scores and generate packing lists" — no real machine learning, a scoring risk against winners running deep-tech ML.

Actual

There's a genuinely trained model behind that: backend/src/ml/logisticRegression.js — hand-rolled batch gradient descent with L2 regularization, trained on a 4,000-example synthetic-but-domain-grounded corpus, printed loss curve, held-out accuracy/precision/recall, shown per-destination on the Risk Overview page next to (not instead of) the rule-based TSI. The critique is correct that Gemini itself never scores anything — that's a deliberate design choice, not the whole AI story.

Demo & Q&A playbook

What's genuinely worth rehearsing from that critique — the correct half of it — is narrative, not code.

The AI-layering defense

Don't claim AI was rejected — claim it was placed correctly, which is the stronger and more accurate position: "We use three different techniques because they solve three different problems. Anomaly detection and SOS triggers are deterministic, threshold-based rules — a false negative there is a life-safety failure, and every threshold has to be auditable, not a black box. The Predictive Risk Score is a real trained model — gradient descent, held-out test accuracy, printed loss curve — because it's advisory, shown alongside the rule-based score, never gating an alert on its own. Gemini only ever explains a score that's already been computed by one of those two — it never decides anything, and there's an offline fallback if the call fails. That's not fear of AI. That's knowing which layer probabilistic reasoning belongs in and which layer it doesn't."

If pressed on why not a deep-tech agentic planner: "An agentic planner optimizes for capability. A dispatch system in a life-safety context optimizes for the worst case being explainable to the family and the officer who acted on it. Those are different design goals, and we chose the one this problem actually has."

The airplane-mode runbook

01

Open the tourist app on the demo phone with the govt dashboard already visible on the main screen, live map centered on the demo tourist's last known position.

02

Physically enable Airplane Mode on the phone, on camera — no cutting away. State out loud that GPS still works without a data connection.

03

Trigger SOS. Narrate what's happening while it sends: satellite coordinates dropping to a structured SMS (AARAKSHA_SOS|ID:...|LAT:...|LNG:...), no app server round-trip required.

04

Cut to the govt dashboard. The Twilio inbound webhook should already have parsed the SMS and created a real SOS event — point at the marker appearing on the live map, not a canned screenshot.

05

Close the loop: assign a rescuer from the dashboard, switch the map to 3D, and let the panel watch the live GPS marker move along a real OSRM road route toward the SOS — this is where the "novel/immersive" critique gets answered without saying a word about it.

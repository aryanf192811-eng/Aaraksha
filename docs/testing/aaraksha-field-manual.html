Shared-environment ground rules

Everyone is testing against the same live database

The demo accounts below are shared — if you resolve Rahul Verma's active SOS or complete Priya Deka's rescue job, the next teammate to open that account sees a blank state instead of the scenario it was built to demonstrate.

Rule of thumb: use the seeded demo accounts to view pre-built states. For anything destructive or one-time — triggering a fresh SOS, testing account deletion, filing a real E-FIR, registering — create your own throwaway account (a fake name and a phone number nobody else is using works fine; any Aadhaar number that passes the Verhoeff checksum will do, or just try a few — most won't validate, and that's the point).

First request after a quiet period is slow

The backend runs on a free tier that spins down after ~15 minutes with no traffic. The first request after that can take 50+ seconds while it wakes up — refresh once and it'll be normal-speed for the rest of your session. Not a bug.

What's running in fallback mode — don't file these as bugs

Three optional third-party integrations were deliberately left unconfigured on this deployment. The app is built to degrade gracefully when they're missing — that's the intended behavior, not broken functionality.

IntegrationWhat you'll actually see
Twilio (SMS)No real SMS is sent. Forgot-password OTPs show up directly in the app's UI instead of arriving by text — that's the built-in dev fallback, not a delivery failure. The offline-SOS-over-SMS mechanism can't be demonstrated in this deployment at all (it needs a real phone number bound to Twilio) — treat that feature as "reviewed via code, not live-testable here."
Gemini (AI)AI-generated packing lists and the AI Safety Briefing both fall back to static, pre-written content instead of a live model call. The UI won't look broken — it'll just be the same fallback text every time.
OpenWeatherMapLive weather no longer feeds into the Travel Safety Index. TSI scores you see are the rule-based terrain/connectivity/season factors only, weather delta will read as neutral.

01 First look — dashboard & trip safety

  1. Log in as Aryan Demo. The dashboard opens directly to the active trip, showing a TSI score out of 100.
  2. Tap the active trip card. Full itinerary, stops, and per-stop risk detail.
  3. Switch the app language (Profile → language selector) to Hindi, then Assamese. Every label changes — flag anything left in English.

02 Plan a trip from scratch

  1. From My Trips, start a new trip. Add 2–3 stops from the destination catalog.
  2. Set a budget and dates, save. A TSI score appears automatically, no manual trigger.
  3. Open the AI packing list feature. Static fallback content (see limits section) — this is expected, not a bug.

03 SOS — on your own throwaway account

  1. Register a fresh account (don't use a demo account for this one).
  2. From the Safety Center, hold the SOS button for the full 2 seconds. A confirmation state, then an active SOS is created — check it shows up correctly under "My SOS History."
  3. Try releasing the hold early (under 2s). No SOS should fire — this is the accidental-press guard.
  4. Set up a Dead Man's Switch with the shortest interval available. Let it lapse without checking in. An SOS auto-fires with your last known location, no action from you.

04 File an E-FIR

  1. From Safety Center, choose "File a Report" (distinct from the SOS button — this is for something that already happened).
  2. Attach a photo containing a car, bag, or similar object. On-device detection tags what it sees and may suggest a category — always overridable.
  3. Submit and check "My Reports" for the case number and status.

05 Privacy & data rights

  1. On your own throwaway account (never a shared demo account), open Profile → Privacy.
  2. Export your data. A real file download — open it and confirm no password hash or other secret is in there.
  3. Request account deletion while you have an open SOS. Denied, with a stated reason.
  4. Resolve the SOS, then request deletion again. Succeeds — and you should no longer be able to log back in with that account.

04 Volunteer verification

  1. Register a new volunteer from the Rescuer App (see that section) if none are pending review.
  2. As Super Admin, open the volunteer verification queue and approve the pending one. Full identity detail shown before you approve — check nothing's truncated or missing.

05 Accessibility pass

  1. Try navigating the SOS detail modal and the E-FIR detail modal using only the keyboard (Tab to move focus, Escape to close).
  2. Focus should land inside the modal on open, a visible ring should show on every focused control, and Escape should close it.

The flagship end-to-end flow

This is the one flow that proves every portal is really one system, not four separate demos. Best done with two people — one on the Tourist app, one on Govt — but doable solo across browser tabs.

Tourist: fresh throwaway account → Trigger SOS → Govt: SOS appears live on map → Assign a rescuer → Rescuer: job appears → Mark EN_ROUTE → Guardian link: shows it live
  1. Register a throwaway tourist account. Grab its Guardian link from the Profile page and open it in a separate tab or a different device.
  2. Trigger a real SOS (hold 2s). Watch it appear on the Govt Command Center's live map without a page refresh.
  3. As a govt operator, open the SOS and assign the "Recommended" rescuer.
  4. Log into the Rescuer App as whichever volunteer or team got assigned. Confirm the job shows up with a real road route.
  5. Mark EN_ROUTE, then ARRIVED, from the Rescuer App.
  6. Check the Guardian link the whole time. Every state change — SOS active, rescuer assigned, rescuer en route — should show up there live, without anyone touching that tab.
  7. As the govt operator, resolve the SOS to close the loop.
